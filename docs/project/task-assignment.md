## 一 分工结论

建议采用四人方案：成员 A 负责前端编排与请求，成员 B 负责后端路线与算法，成员 C 负责地图交互与可视化，成员 D 负责后端存储、通勤记录与数据库集成。此分工延续现有项目中 A 偏应用集成、B 偏后端、C 偏地图的职责，并增加 D 分担后端的数据一致性工作。

三人时建议按能力重新分成一个前端负责人、一个路线后端负责人和一个数据后端负责人；前端负责人合并四人方案中的 A 与 C。此时前端工作量明显增加，应延长交付周期或分批交付，而不是假设少一个人仍能保持相同工期。若团队只有一人能处理后端，可保留 A、B、C 原职责，由 B 合并 D，并采用分批交付方案。

以下任务是计划，不表示代码已经修改。成员姓名可在认领时补充。每个人都要为自己的改动编写必要测试并更新说明，集成负责人不代替开发者完成所有测试。

## 二 工作量与实施边界

首轮交付包括 P0 正确性修复和 P1 核心功能优化，以及对应的测试、迁移和文档。P2 分时段推荐、个人偏好和性能扩展不计入本轮工期。

| 四人成员 | 主要职责 | 预计投入 | 适合能力 |
| --- | --- | --- | --- |
| A | 前端请求、页面流程、状态编排和 API 联调 | 5 至 6 人日 | React、TypeScript、异步请求 |
| B | 步行路线、候选校验、评分、来源和推荐原因 | 5 至 6 人日 | Java、业务算法、接口设计 |
| C | 地图反馈、路线展示、弹层、趋势图和移动端交互 | 4 至 5 人日 | React、CSS、地图和交互 |
| D | 快照存储、通勤幂等、来源过滤、迁移和集成验收 | 6 至 7 人日 | Java、SQL、PostGIS、集成测试 |

合计初估为 20 至 24 人日，已经包含各自测试、接口设计和联调投入。这是对启动书原 14 至 20 人日估算的细化修订，新增接口贯通、并发幂等和迁移验证后预留了更多时间。M0 完成后再校准，不将估算当作固定承诺。

四人按每天约一个完整人日投入，建议预留 8 至 10 个工作日；三人按推荐合并方式预留 11 至 14 个工作日。日历周期受接口依赖和联调影响，不能直接用总人日除以人数。

逐任务量化后，四人基础估算为 A 44 工时、B 44 工时、C 40 工时、D 48 工时，合计 176 工时或 22 人日。D06 的浏览器与移动端验收由 C 协助 4 工时，已经包含在合计中。三人合并时重新核算共同准备和验收分配，详见[成员工作量量化表](workload.md)。

## 三 所有人开始前共同完成的任务

### S00 建立运行基线和接口契约

负责人：D 组织记录，A、B、C 各确认自己的模块。

先运行前端构建、前端单元测试和后端检查，记录现有失败、运行环境以及复现步骤。将启动书中的问题区分为已复现缺陷、源码可确认的行为和待验证风险，防止把环境问题归入功能缺陷。

随后共同确定以下契约，由 D 汇总成一份文档：

1. 路线来源、反馈来源、评分状态、推荐原因及错误结构。
2. 比较结果的查询标识、保存时机、归属校验和过期策略。
3. 通勤提交标识的生成、复用、重复返回及冲突处理规则。
4. 无路线、单路线、无有效评分、模拟结果的响应示例。
5. 标签新增、预计时长、历史记录兼容及数据库迁移顺序。
6. 地图底图与后端服务状态各自控制哪些操作。
7. 临时设备标识的生命周期、页面刷新后的归属保持，以及 demo 服务重启后快照失效的恢复方式。

A 根据契约维护前端公共类型；B 维护路线相关 Java 模型；D 维护通勤模型、仓储接口和迁移；C 在明确 Props 后使用这些类型开发展示组件。

交付：基线检查记录、接口字段和状态示例、任务认领表。接口与组件样例先准备好，前端可通过受控测试数据并行开发，不必等待真实外部服务接通。

## 四 成员 A 前端编排与请求

主责范围：frontend/src/App.tsx、services、types、pages，以及按职责新增的 hooks。A 是公共 TypeScript 类型、页面导航和应用级状态的唯一主改人。

### A01 统一请求和错误处理

对应启动书：T04、第一阶段 4.3。

修改 API 客户端，支持超时、主动取消、统一错误分类和关键响应结构检查。区分网络错误、服务错误、格式错误和取消操作；设备标识存储失败时使用受控会话回退。路线请求透传取消信号，不对写入自动重试。

交付与验收：超时能够结束加载；HTML 和畸形响应得到可理解错误；取消请求不提示失败；相关请求层测试通过。

前置依赖：S00 错误结构；可与后端接口实现并行。

### A02 修复路线预览和演示入口

对应启动书：T02、T04。

恢复真实错误状态和重试按钮；起终点变化重新查询；取消或忽略旧响应。演示路线按端点组合明确选择，无匹配时显示无演示路线。统一使用 B 提供的来源与评分状态，不自行猜测后端是否回退。

交付与验收：非默认端点不会套用默认模拟路线；快速更换端点只显示最后一次结果；错误、无路线、单路线和演示入口均可操作。

前置依赖：A01；S00 路线响应示例。最终联调依赖 B01、B02。

### A03 导航和能力状态编排

对应启动书：T07、T11。

分别管理底图、后端、路线和反馈来源状态；向 C 的组件传入统一能力信息。增加返回、修改起终点和重新规划；更换端点后清理旧路线 ID 和旧通勤状态。刷新后恢复轻量配置，重新请求路线和趋势。

交付与验收：离线底图与后端不可用不会混为一种状态；受限操作无法从其他入口绕过；返回与重新规划不携带旧结果；浏览器返回行为一致。

前置依赖：S00 能力表；与 C01 同时联调。

### A04 反馈刷新与通勤请求对接

对应启动书：T06、T08。

保存当前有效视口；反馈成功后刷新该范围，刷新失败只重试查询。接入 D 的通勤请求，传递比较结果标识、路线 ID、用户感受和稳定操作 ID；网络失败重试复用操作 ID，新通勤生成新 ID。评分和预计时长由服务端快照提供。

交付与验收：写入成功但刷新失败不会重复提交；一次通勤重复操作不增加计数；不足一分钟路线能够完成；成功写入后趋势更新或给出独立刷新警告。

前置依赖：S00 反馈事件契约；真实通勤联调依赖 D01 与 D02。与 C02 使用约定回调并行开发，随后联调，不互相等待实现完成。

### A05 趋势历史数据和状态整理

对应启动书：T11、第二阶段 5.4 与 5.5。

将趋势与历史的查询状态独立管理，提供失败重试和旧数据刷新提示。接入已有历史查询，实现最近查询列表和入口，恢复端点后重新规划。按需要抽离 hooks，保持 App 只负责应用流程和状态组合。

交付与验收：无记录与查询失败可区分；历史结果不会作为当前评分直接使用；结构调整后 A01 至 A04 的行为测试继续通过。

前置依赖：A03 和 S00 数据示例。与 C05 先约定 Props 后并行开发，最终接入 D05 的真实响应。

## 五 成员 B 后端路线与算法

主责范围：external 路线提供器、RouteComparisonService、RouteScoringStrategy、WeightedStressRouteScoringStrategy、GeoMath、HeatmapService、路线领域模型与 RouteController。

### B01 步行路线与候选校验

对应启动书：T01、第一阶段 4.1。

将出行方式明确为步行，按实现时官方文档核对服务接口。解析并验证坐标、折线、正数耗时和距离；处理无路线、单路线、外部超时和异常结构。模拟路线只能由明确策略启用并带来源。

交付与验收：步行请求与业务参数一致；单路线不会被人为补成两条；异常候选不会进入评分；外部服务测试使用可控响应，不依赖每次访问真实服务。

前置依赖：S00 出行方式与错误契约。

### B02 来源和评分状态贯通

对应启动书：T02、T03、T07、T09。

返回独立的路线来源、反馈来源和评分状态。D 提供来源过滤后的报告查询，B 使用其结果聚合评分。模拟固定暴露值和参考量仅用于演示，不能让前端把结果识别为有效真实评分。

交付与验收：真实路线加模拟反馈不会显示为真实有效推荐；有效零分与无评分可区分；A、C 能直接依据响应展示状态。

前置依赖：D03 的查询接口可用；可先根据契约编写服务测试。

### B03 路线采样与评分修正

对应启动书：第一阶段 4.6。

采用沿整条路径累计距离采样或长度加权方案，消除短线段密度带来的偏差。保护空路径、重复点、零长度线段和异常间隔；区分环境感受与综合推荐分，统一数据充分程度的含义。

交付与验收：同一路径插入共线点后评分在约定误差内保持一致；建议采用不超过 0.1 分的固定回归阈值；不存在 NaN 或无穷结果；算法边界测试通过。

前置依赖：S00 评分定义；与 B01 可独立开发。

### B04 推荐原因与快照生成

对应启动书：T10、第一阶段 4.5、第二阶段 5.2。

为无替代、差异不足、绕行过长、数据不足和推荐同一路线等情形返回结构化原因。比较结果通过 D 的仓储接口保存快照并返回标识，包含设备归属、候选路线、来源、评分版本和预计秒数。

交付与验收：各原因与实际判定分支对应；本次出行推荐不使用次日文案；快照保存失败不能返回可完成通勤的有效标识；快照内容足以重建通勤记录所需评分。

前置依赖：B01 至 B03、D01 仓储契约。B 修改 RouteComparisonService，D 不直接修改该服务。

### B05 后端路线验证与说明

为 B01 至 B04 补齐必要单元和接口测试，更新来源、评分和推荐说明。列出真实外部服务连接检查与可控响应测试的区别，说明环境导致的未验证项。

交付与验收：路线、评分、聚合和推荐相关测试通过；接口示例可供 A、C 使用；与 D 快照保存、读取的联调通过。

## 六 成员 C 地图交互与可视化

主责范围：features/map、features/routes、TrendPanel 展示组件及其样式。C 是 MapSurface、FeedbackPanel、RoutePanel 和地图适配器的唯一主改人；不在展示组件中直接新增 API 请求。

### C01 路线状态与地图一致展示

对应启动书：T03、T07、T10。

依据 A 传入的能力和 B 定义的状态渲染地图、卡片及图例。无有效评分时不显示占位零分或舒适标签；分别显示环境指数与预计耗时；保持地图和卡片选择联动。底图模式变化通过事件通知 A。

交付与验收：真实、演示、评分不足、单路线及无路线均正确显示；预览与地图含义一致；点击任一入口同步选择对应路线。

前置依赖：S00 Props 与状态样例；后端未完成时可使用示例数据开发。

### C02 反馈失败恢复与提交状态

对应启动书：T05、第一阶段 4.4。

失败时保留草稿、坐标和面板，提供可见错误；成功后关闭并播放动画。提交期间阻止重复触发，区分新增与重复结果。A 负责写入与刷新编排，C 负责本地草稿和交互状态。

交付与验收：模拟提交失败后所有输入保留；重试操作可用；成功和重复结果显示准确；刷新失败不会清空重新填写的草稿或触发第二次写入。

前置依赖：S00 反馈返回结构。先用受控回调开发，随后与 A04、D04 联调。

### C03 反馈入口与正向标签

对应启动书：T12、第二阶段 5.3。

增加显式反馈按钮与选点确认，保留长按。根据公共标签定义增加安静、树荫、开阔等原因；热力详情显示中文名称、数量、有效时间和来源，未知标签有回退文案。

交付与验收：按钮和长按均可完成反馈；确认前不误报位置；新增标签能够从选择到保存再到展示；显示使用的数据由 B、D 返回，不在前端虚构。

前置依赖：A 维护公共类型；D03 完成枚举与约束后联调。

### C04 地图弹层与移动端操作

改进地图边缘弹层的位置、可滚动区域、键盘焦点和关闭操作；避免地图拖动、长按和按钮点击互相触发。控制热点、路线和图例层级，保持关键信息可读。

交付与验收：390×844 及一个更窄视口无关键控件遮挡与横向溢出；鼠标、触摸、键盘可完成主要操作；地图拖动不会误提交反馈。

前置依赖：C01 至 C03 的基础交互完成。

### C05 趋势图与展示组件测试

对应启动书：T12、第二阶段 5.4。

增加七日折线图及数量展示，保留明细；空日期不补零、不跨缺失段误连。展示 A 提供的加载、空数据、失败和刷新提示，并提供重试回调。通勤评价如纳入本轮，使用 D05 确定的字段。

交付与验收：零记录、单点、跨日与缺失日期均可读；图表和表格数据一致；C 所有组件相关测试通过。

前置依赖：S00 中与 A 约定的状态和数据口径；图表使用示例独立开发，最终与 A05、D05 联调。

## 七 成员 D 数据存储与集成

主责范围：repositories 全部接口与实现、CommuteService、ReportService、TrendService、通勤与报告 DTO 和控制器、数据库迁移及集成测试。D 汇总接口文档和最终检查结果，其他成员提供自己模块的证据。

### D01 快照存储与读取

对应启动书：第一阶段 4.5。

扩展路线查询仓储，提供保存后返回查询 ID、按 ID 和设备读取、有效期判断等能力；demo 与 postgres 的语义一致。与 B 约定快照字段和保存失败处理，并验证读取的设备归属。

交付与验收：B 可保存并获得可用标识；快照不可被其他设备读取使用；缺失、过期和 demo 重启后失效结果得到明确错误并支持重新查询；内存与 JDBC 业务语义一致，持久化差异得到说明。

前置依赖：S00；仓储接口在早期先交付，持久化实现随后完成。

### D02 通勤幂等与服务端评分

对应启动书：T08。

完成通勤使用查询标识读取快照，校验路线和来源，拒绝演示结果进入真实统计。按设备与操作 ID 保证只保存一次；并发重复请求返回一致结果，相同 ID 携带不同业务内容返回明确冲突。

保存服务端评分和预计秒数，兼容历史分钟字段但不推断实际时长。为 A 提供成功、重复成功、冲突、过期等样例。反馈成功评价如加入，应与同一次通勤关联。

交付与验收：并发重复请求只保存一条；前端无法篡改评分；不足一分钟路线能够保存；真实记录不会携带演示评分；趋势只计一次。

前置依赖：D01；B04 快照生产和 A04 请求对接。

### D03 来源隔离与数据库迁移

对应启动书：T09、正向标签与数据库变更。

补齐模拟记录筛选及统计口径，将新增标签同步到 Java 枚举、数据库约束与种子数据。用新增 Flyway 迁移处理快照、来源、预计时长及幂等约束，不改写已执行的 V1 至 V3。

所有迁移文件由 D 统一编号，B 提供需要的字段但不另开相同版本迁移。对历史来源和时长保持未知口径，验证全新数据库及旧库升级路径。

交付与验收：真实查询不混入模拟反馈；新旧标签可读取；迁移无编号冲突；升级和全新初始化均通过；内存模式的筛选规则一致。

前置依赖：S00 字段和兼容规则；优先交付来源过滤接口。

### D04 报告写入与限制结果

沿用已有报告限频和时间空间去重，核对 demo 与 postgres 行为。为新增成功、重复报告、限频和参数错误提供稳定响应；必要时修正并发重复检查，保证 C 可以准确展示结果。

交付与验收：不同失败原因可识别；重复反馈不会当作新增反馈计数；已有合法报告与参数校验继续工作；报告保存和热力刷新可由 A 分别处理。

前置依赖：S00；与 C02、A04 同时联调。

### D05 趋势与历史数据兼容

核对日期时区、空日期、预计时长和来源筛选口径，调整 DTO 与历史查询结构。历史记录缺少新字段时明确标记，确保现有记录不会使趋势和前端历史页面解析失败。

交付与验收：同一次通勤重复写入不增加趋势次数；跨日和空日期正确；历史数据兼容；A、C 使用同一字段与口径。

前置依赖：D02、D03；历史查询字段可提前约定。

### D06 数据库与端到端验收组织

组织全新建库、旧库迁移、并发幂等与归属校验的集成测试，汇总全流程、离线恢复和移动端检查。D 主改共享 E2E 场景和验收记录；C 固定承担 4 工时的浏览器与移动端验收协助，A 按联调需要参与，失败问题回到对应成员修复。D06 总估 8 工时，D 与 C 各计 4 工时，不重复计数。

交付与验收：形成实际运行结果、未运行项、剩余缺陷和启动说明；通过启动书规定的关键场景；环境缺失导致跳过的检查不计为通过。

前置依赖：各成员核心任务完成；测试场景设计在第一天开始，不能等到最后才准备。

## 十 三人方案与减量规则

### 10.1 推荐的三人合并方案

此方案要求至少两人能够处理后端，适合前端经验较强的成员承担界面与应用集成。

| 三人角色 | 对应四人任务 | 预计投入 | 实施重点 |
| --- | --- | --- | --- |
| 前端负责人 | A01 至 A05、C01 至 C05 | 9 至 11 人日 | 先请求和反馈正确性，再做地图展示与图表 |
| 路线后端负责人 | B01 至 B05 | 5 至 6 人日 | 尽早提供来源字段、候选样例与推荐原因 |
| 数据后端负责人 | D01 至 D06 | 6 至 7 人日 | 尽早提供快照接口与迁移，承担集成验收组织 |

总投入仍约 20 至 24 人日，建议 11 至 14 个工作日。后端成员完成本模块后协助编写浏览器场景、整理样例和执行回归，使前端负责人集中处理交互开发。三人角色名称不强行套用原成员字母，应按实际能力认领。

### 10.2 只有一名后端成员时

保留原 A 前端编排、B 后端、C 地图职责，由 B 合并四人方案中的 B 与 D，后端投入约 11 至 13 人日，整体建议预留 13 至 16 个工作日。A/C 负责更多 E2E 场景和联调记录，但后端关键计算与数据库修改仍由 B 主改。

若期限不足，首批保留 A01 至 A04、B01 至 B04、C01/C02、D01 至 D04 及其必要测试。C04 的基本可操作性必须保留；导航保留返回和重新规划。将完整趋势图、历史查询页面、正向标签扩展、高级选点和非必要重构放到第二批。

减量是缩小首批范围，不是降低正确性要求。缺失评分不能当成零分，演示数据不能混入真实统计，失败反馈必须能恢复，同一通勤不能重复计数。

## 十一 统一交付和完成标准

每位成员提交代码、必要测试、配置或迁移说明、界面或接口示例，以及已知限制。任务完成应同时满足：

1. 修改能够解决对应问题，异常场景也有明确行为。
2. 相关单元或集成检查通过；未运行项注明原因。
3. 与上下游使用一致的字段、状态和参数含义。
4. 涉及存储时兼容已有数据，demo 和 postgres 不出现相反行为。
5. 说明与实际实现一致，另一个成员能依说明启动和验证。

对临时设备标识、页面刷新、服务重启和比较结果过期单独验证。身份或快照失效时引导重新查询，不自动更换身份后继续写入旧通勤结果。

团队最终交付一个可运行的稳定版本、数据库迁移、接口说明、测试汇总和启动说明。分时段推荐、个人偏好、性能优化及额外平台发布在本轮验收后单独估算和认领。
