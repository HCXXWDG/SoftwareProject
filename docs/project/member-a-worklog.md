## 已实现的行为

请求层对网络、超时、取消、HTTP、业务与格式错误作统一表达。默认超时 10 秒，可通过 `VITE_API_TIMEOUT_MS` 或单请求参数调整，期限覆盖响应体读取。GET 与 POST 都不自动重试；写入超时提示可能已保存。真实环境文件不随提交上传。

浏览器存储不可用时，同一页面会话复用临时设备 ID，并给出保存限制。运行时验证器以当前后端结构为准，兼容 Jackson `NON_NULL` 省略字段，将应为空的值归一化为 `null`，不填零。

路线失败不自动转换成演示成功。仅预设端点组合提供演示路线，其他组合明确提示无演示。没有明确的真实路线、真实反馈与有效评分三项状态时，不显示有效评分或舒适标签。当前新增的可选来源字段只是前端兼容草案，不能替代后端协议。

反馈的写入结果与热力查询结果分开记录：创建成功后刷新最近视口，409 duplicate 作为重复结果处理，不重复 POST、不假装新增热点。被新视口查询替代的刷新与真正查询失败分开。离开行程后，即使再次进入相同端点，旧反馈响应也不能刷新新行程或显示旧提示。

为接入上述 A 的能力与回调，对 C 的组件做了必要的小范围适配：MapSurface 增加底图模式回调和反馈能力输入；反馈失败保留草稿并显示错误；服务失效时禁用提交并说明原因；重复反馈不播放新增动画。地图算法、配色和主要布局未调整，仍需 C 复核。

## 通勤记录的当前限制

现有 `CommuteService` 每次创建新 UUID 并保存，没有操作 ID 去重、服务端快照、设备归属或过期校验。现有路线后端还可能在外部服务失败时返回模拟结果，HTTP 成功不能证明是真实路线。

本批停止由页面发送旧式客户端评分通勤写入，按钮明确禁用并说明原因；历史趋势仍可查询。没有把前端按钮锁当作后端幂等，也没有发送虚构字段宣称完成。D01/D02 和 B02/B04 完成后，需要按确认的契约接入并重新开启。该限制会影响现有通勤写入流程，应在合并前由团队明确接受或补齐后端依赖。
