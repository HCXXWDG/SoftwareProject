## 本轮实现

App 在欢迎页、预览页和地图页持续挂载通勤恢复区。到达后明确选择五档感受，再提交所选路线的服务端快照；无评分 REAL 与 DEMO 可以记录，评分展示仍独立判断。DEMO 确认结果明确说明不进入真实趋势或通勤历史；省略评分显示“暂无路线评分”，真实零分保留。趋势首次查询失败不会阻挡通勤。

新建提交要求当前所选路线存在、有效 UUID 快照、支持的来源和数据服务可连接，底图离线不阻断。增加 `VITE_COMMUTE_RECORDING_ENABLED=true` 的明确部署开关，默认 false；旧服务不因此获得写入入口。须先部署并验收 D07/V6 后再设置构建环境。开关开启并不免除服务端的归属、过期和幂等校验。

恢复重试使用原 snapshotId、routeId、感受、operationId 和 completedAt，不依赖刷新后产生的新比较结果，也不要求重新选路线。恢复不自动 POST，不能用新建操作覆盖待确认记录。实际设备/API 会话变化、存储损坏或无法可靠读回仍阻止写入。

确认成功后只刷新趋势与路线查询历史；查询失败显示独立警告，按钮只重试 GET。自动/手动查询刷新时显示进度并禁用下一次通勤，避免按钮无反馈。明确开始下一次通勤才重置已确认状态并重新规划。行程版本、页面状态或快照改变后，迟到回执不刷新新行程；迟到查询失败也不追加旧警告。

### 实际后端浏览器覆盖

1. 390/320px 各一项：从真实 compare 获取 DEMO 快照和无评分候选，选择另一条路线与 0 档真实感受，首次完成返回 201。请求只有五个白名单字段，UI 显示无评分和演示排除，刷新后的趋势显示排除 1 次，页面无水平溢出；明确开始下一次后进入新预览。
2. 回执丢失恢复：浏览器请求交给真实 D07 保存并取得 201 后，仅丢弃网络回执，不替换任何 API 数据。刷新页面生成新快照但不自动 POST，恢复区保持原感受；显式重试原请求返回 200 duplicate、同 commuteId，两个请求体完全相同，确认后清理恢复信息。

本轮真实浏览器服务使用隔离内存 demo；数据库迁移 V6、本轮真实高德连接、Android 与生产环境均未运行。当前尚不能把 D06/#69 的旧验收或 B 旧头的 CI 结果当作 D07 组合数据库验收。

## 复跑

```powershell
$env:MEMBER_A_D07_API_URL='http://127.0.0.1:18083'
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:e2e:member-a-commute
```

配置会启用 D07 写入开关、使用空地图 key，在 5403 启动独立前端，结果写入仓库忽略目录 `.tmp/member-a-commute-browser`，不被共享浏览器套件清理。每项使用独立匿名设备；内存数据仅用于隔离验收。PWA 和共享浏览器命令仍沿用原配置，默认不启用通勤写入。
