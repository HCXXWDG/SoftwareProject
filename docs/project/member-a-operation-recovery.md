日期：2026-10-22。继续草稿 PR #56，不合并或发布其他成员分支。本轮以已发布 A 提交 `69e67ae` 的相同文件树为基线；D07 契约核对为 PR #71 的 `5b0964bf`。

## 已实现

新增 `pendingCommute` 与 `useCommuteOperation`。首次显式提交前固定 snapshotId、routeId、五档到达感受、operationId、completedAt，只保存协议白名单；安全随机操作号不可用或存储无法写入并读回时不发送 POST。同一操作不可被新路线、感受或另一服务覆盖。

恢复信息绑定实际请求使用的匿名设备身份、API 地址与页面来源，存于当前标签页 sessionStorage。刷新或重新挂载只恢复状态，不自动写入；显式重试复用原请求。浏览器关闭、主动清除存储后的恢复不在此能力范围内。

同步锁防止双击并发。网络、超时、取消、回执格式错误及 409/404/410 均保留原操作，不能通过重新开始绕过。D 当前先检查快照再执行幂等，因此快照过期不能证明原请求没有写入；404/410 提示先核对记录，不自动换操作号。

完整成功回执确认后，才清理完全匹配的恢复信息，并单独触发查询刷新。刷新失败保留成功状态，不重发 POST；清理失败或已有其他恢复信息会阻止开始下一次通勤。设备、服务、行程或挂载上下文变化后，旧回执不触发新行程的刷新。

D07 的通勤成功体只返回 selectedScore，不返回 fastestScore/confidence；其中 selectedScore 允许省略或 null。前端响应检查接受这两种合法形态并统一为 null，保留真实 0，拒绝字符串、非有限值和越界分数。201 created / 200 duplicate、操作归属、路线与感受匹配仍严格检查。旧版服务的 422 兼容提示保留，不将它视为 D07 的写入策略。
