## 1. 验收环境与证据口径

| 非预设历史端点被替换 | 从历史重新规划，再进入“修改起终点”，不修改直接比较，会变成默认点位；近似匹配还会把接近预设点的坐标吸附到预设坐标 | WelcomePage 增加历史点位选项；App 仅精确匹配预设经纬度，其余保留原坐标与名称。浏览器核对修改前后两次 compare 请求，含与预设点相差 `0.0000005` 度的起点；相同坐标即使 ID 不同也不能规划 |

## 5. 复跑方法

需已安装项目依赖、Java 17 或更高版本、本机 Chrome。先在 `backend` 执行 `./mvnw.cmd package` 生成与源码一致的 `target/commute-mood-api-1.0.0.jar`。本轮复用了此前已构建且源码未变化的 JAR。

在 `frontend` 执行：

```powershell
npm run build
npm test
$env:PLAYWRIGHT_CHANNEL='chrome'
npm run test:e2e:member-a
node node_modules/@playwright/test/cli.js test e2e/member-a.e2e.ts --workers=1
```

`npm test` 当前预期仍报告上面的 3 项既有失败，不能因其退出码非零省略报告。真实接口套件使用 5181 / 18081，受控套件使用 5173，端口冲突时先结束占用服务；独立配置拒绝复用已有服务，避免混淆验收环境。
