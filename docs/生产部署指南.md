# 生产环境部署指南

## 架构

```
用户(HTTPS) → Nginx/Caddy(:443) → Spring Boot(:8080) → PostgreSQL(:5432)
                                      ↑
                              APP_CORS_ORIGINS 需包含前端域名
```

## 1. 后端 API 部署

### 1.1 环境变量（生产）

```bash
# .env
SPRING_PROFILES_ACTIVE=postgres
POSTGRES_DB=commute_mood
POSTGRES_USER=commute
POSTGRES_PASSWORD=<强随机密码>
POSTGRES_PORT=5432
DEVICE_HASH_SALT=<强随机盐>

# 高德 Web Service Key（后端用，绝不暴露给前端）
AMAP_WEB_KEY=<你的高德 Web 服务 Key>

# CORS：逗号分隔的前端域名
APP_CORS_ORIGINS=https://your-pwa-domain.com,capacitor://localhost,http://localhost
```

### 1.2 数据库

```bash
docker compose -f infra/compose.yml --env-file .env up -d postgres
```

### 1.3 后端

```bash
docker compose -f infra/compose.yml --env-file .env up -d api
```

## 2. HTTPS 反向代理

### Nginx 示例

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        root /var/www/commute-mood-frontend;
        try_files $uri $uri/ /index.html;
    }
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

### Caddy 示例

```
your-domain.com {
    reverse_proxy /api/* localhost:8080
    root * /var/www/commute-mood-frontend
    try_files {path} /index.html
    file_server
}
```

> Caddy 自动获取和管理 Let's Encrypt 证书，推荐使用。

### 获取 SSL 证书

```bash
# 使用 Certbot (Let's Encrypt)
sudo certbot certonly --standalone -d your-domain.com

# 或使用 Caddy（自动）
# 直接启动 Caddy，证书自动获取
```

## 3. 前端 PWA 部署

### 3.1 构建

```bash
cd frontend
cp .env.production.example .env.production
# 编辑 .env.production，填入实际值
npm ci
npm run build
```

### 3.2 部署静态文件

```bash
# 将 dist/ 目录复制到 Web 服务器
# Nginx 示例：
cp -r dist/* /var/www/commute-mood-frontend/
```

### 3.3 PWA 要求

- 必须通过 HTTPS 访问（Service Worker 要求）
- 根路径部署（`/`），或配置 `vite.config.ts` 的 `base` 字段
- 确保 `manifest` 和 `sw.js` 可被访问

## 4. 高德 Key 轮换

### 4.1 生成新 Key

1. 登录 [高德控制台](https://console.amap.com/)
2. 应用管理 → 我的应用 → 创建新 Key
3. 配置：

| 平台 | 限制方式 |
|------|----------|
| Web 端(JS API) | 域名白名单：`your-domain.com` |
| Android | 包名 `com.jiangnan.course.commutemoodmap` + SHA1 指纹 |
| Web 服务(后端) | IP 白名单（服务器公网 IP） |

### 4.2 更新配置

```bash
# .env（后端）
AMAP_WEB_KEY=<新 Web 服务 Key>

# .env.production（前端）
VITE_AMAP_JS_KEY=<新 JS API Key>
VITE_AMAP_SECURITY_CODE=<新安全密钥>
```

### 4.3 旧 Key 处理

- 在高德控制台停用旧 Key
- 确认新 Key 可正常加载地图后，删除旧 Key

### 4.4 获取 Android SHA1

```bash
keytool -list -v -keystore release.keystore -alias commute-mood-release | grep SHA1
```

## 5. 生产环境检查清单

- [ ] 后端通过 HTTPS 可访问
- [ ] `APP_CORS_ORIGINS` 包含生产 PWA 域名
- [ ] 高德 Key 已轮换并限制域名/IP
- [ ] `.env` 使用强随机 `DEVICE_HASH_SALT`
- [ ] 数据库密码为强随机值
- [ ] `release.keystore` 安全备份（不提交到 Git）
- [ ] PWA 通过 HTTPS 可安装（standalone 模式）

## 6. 回滚方案

如部署后出现问题：

```bash
# 回滚后端容器
docker compose -f infra/compose.yml down
docker compose -f infra/compose.yml --env-file .env up -d

# 回滚前端
cp -r dist-backup/* /var/www/commute-mood-frontend/

# 恢复旧高德 Key（在 .env 中改回旧值）
```
