# 跨平台发布检查清单

> 适用于 Android APK 和 Windows PWA 两种分发渠道。每次发布前逐项核对，全部勾选后方可发布。

---

## 一、通用前置项（成员 A / B / C 共同负责）

- [ ] `develop` 分支 CI 全绿（Frontend CI / Backend CI / E2E CI / Full-stack E2E / Android Build）
- [ ] `CHANGELOG.md` 已更新本次版本变更
- [ ] 前端 `package.json` 的 `version` 与 Android `versionName` 一致
- [ ] 后端已部署到公网 HTTPS 地址（如 `https://api.example.com`），且 `/actuator/health` 返回 `UP`
- [ ] 后端 CORS 配置包含正式 PWA 域名（通过 `APP_CORS_ORIGINS` 环境变量注入）

---

## 二、Android APK 发布

### 2.1 签名配置（成员 A 负责）

- [ ] 生成 release keystore：
  ```bash
  keytool -genkeypair -v \
    -keystore release.keystore \
    -alias jiangnan-commute \
    -keyalg RSA -keysize 2048 -validity 10000
  ```
- [ ] 在 `frontend/android/app/build.gradle` 的 `release` 块配置 `signingConfig`，或通过 CI secrets 注入
- [ ] keystore 文件**不提交到 Git**（`.gitignore` 已排除 `*.keystore`）
- [ ] 在 GitHub repository Settings → Secrets 添加以下变量：
  | Secret 名 | 说明 |
  |-----------|------|
  | `ANDROID_KEYSTORE_BASE64` | `base64 release.keystore` 的输出 |
  | `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
  | `ANDROID_KEY_ALIAS` | key 别名 |
  | `ANDROID_KEY_PASSWORD` | key 密码 |

### 2.2 版本号管理（成员 A 负责）

- [ ] `frontend/android/app/build.gradle` 中 `versionCode` 递增（每次发布 +1）
- [ ] `versionName` 更新为语义化版本（如 `1.1.0`）
- [ ] CI 中的 `Verify versionCode and versionName` 步骤通过

### 2.3 API 地址配置（成员 A 负责）

- [ ] 创建 `.env.android.production`：
  ```
  VITE_API_BASE_URL=https://api.example.com
  VITE_AMAP_JS_KEY=<生产高德 Key>
  VITE_AMAP_SECURITY_CODE=<生产安全密钥>
  ```
- [ ] 构建时使用生产环境变量（不使用 `10.0.2.2` 模拟器地址）
- [ ] `network_security_config.xml` **不**添加生产域名到明文白名单（生产必须 HTTPS）

### 2.4 高德 Key 白名单（成员 A/B 负责）

- [ ] 在高德开放平台控制台添加 Android 应用的 SHA1 指纹：
  ```bash
  keytool -list -v -keystore release.keystore -alias jiangnan-commute
  ```
- [ ] 确认 Key 绑定的包名 = `com.jiangnan.course.commutemoodmap`
- [ ] 确认 Key 绑定的 SHA1 与 release keystore 一致

### 2.5 构建与验证（成员 C 负责 CI，全员验证）

- [ ] Android Build CI 中 `Build Android release APK` 步骤成功
- [ ] `android-release-apk-*` artifact 已上传且非空
- [ ] Android Emulator E2E Smoke 步骤通过（app 成功启动，截图已上传）
- [ ] 真机安装 release APK 后：
  - [ ] 欢迎页正常显示，零 API 请求
  - [ ] 点击"查看预设路线"后成功获取校园路线
  - [ ] 点击"进入地图"后地图限制在校园边界（zoom 15-18，拖出回弹）
  - [ ] 固定起点（绿）/终点（红）标记可见
  - [ ] 长按校园边界内弹出反馈面板，边界外无响应
  - [ ] 390×844 和 412×915 视口无横向溢出

### 2.6 分发

- [ ] 将签名后的 `app-release.apk` 上传到分发渠道（应用商店 / 内测平台 / 直链下载）

## 三、Windows PWA 发布

### 3.1 HTTPS 部署（成员 A/B 负责）

- [ ] 前端 `dist/` 部署到 HTTPS 静态托管（如 Vercel / Netlify / Nginx + Let's Encrypt）
- [ ] 确认 `vite.config.ts` 的 PWA manifest `name` 为"校园通勤情绪地图"
- [ ] 确认 `display: standalone`
- [ ] 确认 192 / 512 / maskable 图标已生成并位于 `frontend/public/`

### 3.2 Service Worker 验证（成员 C 负责 CI，全员验证）

- [ ] `/api/**` 使用 NetworkOnly（不缓存 API 数据）
- [ ] 高德脚本 `webapi.amap.com` 使用 NetworkOnly
- [ ] 地图瓦片 `*.amap.com/*tile*` 使用 NetworkOnly
- [ ] 应用外壳（HTML/CSS/JS/图标）被 precache（离线可启动欢迎页）

### 3.3 安装验证

- [ ] Edge / Chrome 地址栏出现安装图标
- [ ] 安装后以 standalone 模式启动（无浏览器导航栏）
- [ ] 断网时欢迎页仍可加载（Service Worker 缓存应用外壳）
- [ ] 完整三阶段流程可操作

## 四、CI Secrets 配置参考（仓库管理员）

```bash
# 生成 keystore 的 base64（用于 GitHub Secret）
base64 -w 0 release.keystore  # Linux
# 或
certutil -encode release.keystore encoded.txt  # Windows，取编码后内容
```

| Secret | 用途 | 负责人 |
|--------|------|--------|
| `ANDROID_KEYSTORE_BASE64` | release 签名 keystore | 成员 A 生成，管理员配置 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 | 成员 A |
| `ANDROID_KEY_ALIAS` | key 别名 | 成员 A |
| `ANDROID_KEY_PASSWORD` | key 密码 | 成员 A |

---

## 五、回滚方案

- 若发布后发现严重问题：
  1. 在 GitHub 回退 `main` 分支到上一个 release tag
  2. 重新触发 Android Build CI 构建旧版本 APK
  3. 通知用户更新到回滚版本
  4. 修复后发布新版本（`versionCode` 继续递增，不重复）
